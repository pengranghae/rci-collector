# 채용 캘린더 인사이트 — 일정 수집기 (MVP 0.1)

공개된 기업 뉴스룸·공식 페이지에서 채용 일정을 찾아 `inbox.json`으로 정리하는 프로그램입니다.
분석 도구(HTML)의 「수집함」 탭에서 이 파일을 불러와 **사람이 승인한 것만** 분석 데이터에 반영합니다.

- Python 표준 라이브러리만 씁니다. `pip install`이 필요 없습니다.
- 로그인·쿠키·비밀번호를 다루지 않습니다. 로그인이 필요한 사이트(에브리타임, 자소설닷컴 채팅방)는 수집하지 않습니다.
- 사이트마다 robots.txt를 먼저 확인하고, 금지된 주소는 요청하지 않습니다. 같은 사이트에는 3초 간격으로 요청합니다.

## 1. 구성

| 파일 | 역할 |
| --- | --- |
| `collect.py` | 실행 진입점. 수집 → 추출 → 매칭 → 저장 → `inbox.json` 작성 |
| `run.bat` | 윈도우용 실행 파일(작업 스케줄러에 이 파일을 등록) |
| `config.json` | 출처 목록, 요청 간격, 인증서·파일 경로 설정 |
| `pool.json` | (선택) 분석 도구에서 내려받은 비교기업 Pool(단위·소속 그룹 포함). 없으면 내장 기본 목록 사용 |
| `rci/fetch.py` | 페이지·RSS 가져오기, robots.txt 확인, HTML → 본문 평문 |
| `rci/extract.py` | 본문에서 전형 일정을 찾아 날짜로 정규화 |
| `rci/match.py` | 기업명·계열사명 매칭 |
| `rci/store.py` | SQLite 저장(문서, 추출 일정, 변경 이력, 출처별 상태) |
| `tests/` | 로컬 가짜 서버로 하는 자동 테스트와 예시 문서 |

실행하면 생기는 것: `data/collector.sqlite`(저장소), `inbox.json`(검토용 결과), `logs/collect-날짜.log`(실행 기록).

## 2. 설치

Python이 필요합니다. 아래 두 방법 중 하나를 고르세요.

**방법 A — 설치 없이 쓰기(관리자 권한 불필요, 권장)**

1. python.org → Downloads → Windows → 최신 3.12 또는 3.13의 **"Windows embeddable package (64-bit)"** zip을 받습니다.
2. 이 폴더(`rci-collector`) 안에 `python` 폴더를 만들고, 받은 zip을 그 안에 풉니다.
   `rci-collector\python\python.exe`가 있으면 맞게 된 것입니다.
3. `run.bat`이 이 `python` 폴더를 먼저 찾아 씁니다. 시스템에 아무것도 설치하지 않으며, 지울 때는 폴더만 삭제하면 됩니다.

**방법 B — 일반 설치**

python.org에서 설치 프로그램을 받아 설치합니다(첫 화면에서 "Add python.exe to PATH" 체크). 사내 정책상 IT 승인이 필요할 수 있습니다.

**동작 확인(두 방법 공통, 외부 접속 없음)**

```
cd D:\RCI\rci-collector
python\python.exe -m unittest discover -s tests -v      (방법 A)
python -m unittest discover -s tests -v                (방법 B)
```
마지막에 `OK`가 나오면 준비 끝입니다.

## 3. 사용 순서

1. **Pool 맞추기(처음 한 번, Pool을 바꿀 때마다):** 분석 도구 → 비교기업 Pool 탭 → 「수집기용 Pool 내보내기」 → 받은 `pool.json`을 이 폴더에 둡니다.
2. **수집:** `run.bat`을 더블클릭하거나 `python collect.py`를 실행합니다.
3. **검토:** 분석 도구 → 수집함 탭 → 「수집 결과 불러오기」로 이 폴더의 `inbox.json`을 엽니다.
4. 후보마다 '현재 분석 값'과 '수집 값'을 비교하고 원문 링크를 확인한 뒤 **승인 / 보류 / 무시**를 고릅니다.
   - 승인하면 일정 데이터에 '자동수집' 출처로 들어가고, 원문 URL·처음 수집 시각·마지막 확인 시각이 함께 저장됩니다.
   - 기존 값과 달라진 전형은 그 일정의 변경 이력(이전 값, 새 값, 시각, 출처)에 남습니다. 일정 데이터 탭 → 해당 행 「수정」에서 볼 수 있습니다.
   - 같은 파일을 다시 불러와도 이미 처리한 후보는 다시 대기로 오지 않습니다. 내용이 바뀐 후보만 새로 올라옵니다.

### 페이지 하나만 직접 읽기

공식 채용 공고나 보도자료 주소를 알고 있을 때:
```
python collect.py --url https://주소 --source samsung_newsroom
```
사이트가 막혀 있거나 스크립트로 그려지는 페이지라면, 브라우저에서 「다른 이름으로 저장(웹페이지, HTML만)」한 뒤:
```
python collect.py --file 저장한파일.html --url https://원래주소 --source manual --pub 2026-09-07
```
`--pub`은 게시일입니다. 페이지에서 게시일을 찾지 못하면 오늘 날짜로 계산하므로, '24~25일'처럼 월이 빠진 표현이 있으면 꼭 넣어 주세요.

## 4. 정기 실행(작업 스케줄러)

관리자 권한 없이 내 계정으로 등록됩니다. 예: 평일 오전 8시 10분.
```
schtasks /Create /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 08:10 /TN "RCI 일정 수집" /TR "\"D:\RCI\rci-collector\run.bat\""
```
- 확인: `schtasks /Query /TN "RCI 일정 수집"` · 지금 한 번 실행: `schtasks /Run /TN "RCI 일정 수집"` · 삭제: `schtasks /Delete /TN "RCI 일정 수집" /F`
- PC가 꺼져 있던 시간에는 돌지 않습니다. 공채 시즌(8~12월)에만 켜 두는 것을 권합니다.

## 5. 출처 추가

`config.json`의 `sources`에 항목을 추가합니다. 워드프레스 기반 뉴스룸은 대부분 `/feed` 주소에 RSS가 있습니다. 아래 주소는 형식 예시이며 실제 주소는 확인이 필요합니다.
```json
{"id": "lg_newsroom", "name": "LG전자 뉴스룸", "type": "공식", "enabled": true,
 "default_company": "LG전자",
 "feeds": ["https://live.lge.co.kr/feed/"],
 "keywords": ["채용", "신입", "인적성"], "exclude_title": ["경력"]}
```
- `default_company`: 제목에서 기업명을 못 찾을 때 붙일 비교기업 이름(Pool의 이름과 같게).
- `keywords`: 제목·요약·분류에 이 단어가 있는 글만 읽습니다.
- 새 출처를 넣으면 먼저 `python collect.py --source lg_newsroom`으로 한 번 돌려 로그를 확인하세요.
- 추가 전에 그 사이트의 이용약관과 `/robots.txt`를 확인하세요. 수집기는 robots.txt 금지 주소를 건너뛰지만, 약관은 사람이 판단해야 합니다.

### 5-1. 출처 종류 (0.2에서 추가)

| 종류 | 설정 | 동작 |
| --- | --- | --- |
| 기업 공식 뉴스룸 | `"preset": "official"` + `feeds` | 뉴스룸 RSS에서 채용 글을 고름. 그룹 뉴스룸은 `default_company`로 그룹명 지정 |
| 언론사 RSS | `"preset": "news"` + `feeds` | 경제·산업면 RSS의 모든 기사 중 **제목에 Pool 기업명이 있고** 채용 키워드가 있는 기사만 본문을 읽음 |
| 네이버 뉴스 검색 | `"kind": "naver_news"` | Pool 기업마다 `queries`(예: `{name} 신입 채용`)로 검색 → 원문 기사 주소를 읽음. **API 키가 있을 때만** 동작(README_actions.md 6장) |

`presets`(config.json 위쪽)에 언론·공식 출처 공통 설정(키워드, 제외 단어 등)이 있고, 출처에 같은 항목을 적으면 그 값이 우선합니다.

- `require_company: true` — 제목에서 Pool 기업을 못 찾으면 건너뜁니다(‘대기업 채용 동향’ 같은 기사 제외).
- `read_once: true` — 한 번 읽은 기사는 다음 실행에서 다시 요청하지 않습니다(뉴스 기사는 일정이 잘 바뀌지 않음. 공식 뉴스룸은 바뀐 날짜를 잡아야 하므로 끔).
- `tiers` (네이버) — 예: `["핵심"]`이면 Pool에서 핵심 등급 기업만 검색. 비우면 전체.
- 같은 기업·시즌·일정을 여러 매체가 보도하면 **inbox.json에서 후보 하나로 합쳐집니다.** 대표는 공식 출처 → 먼저 수집된 기사 순이고, 나머지 기사는 `alsoReportedBy`에 남습니다.
- 구글 뉴스 RSS는 robots.txt가 자동 수집을 막고 있어 쓰지 않습니다(11/27 확인).


### 출처 후보 점검(`--probe`)

새 출처를 넣기 전에, 회사 PC에서 후보 사이트가 robots.txt로 수집을 허용하는지와 RSS 피드가 있는지 확인합니다.

```
python\python.exe collect.py --probe
```

- 후보 목록은 `probe_sites.json`에 있습니다. 주소를 고치거나 줄을 더해도 됩니다.
- 사이트당 요청은 최대 4번이고, 요청 간격과 robots.txt 규칙은 수집과 똑같이 지킵니다. 저장소(`data`)와 `inbox.json`에는 아무것도 쓰지 않습니다.
- 결과는 화면과 `probe_result.csv`(엑셀로 열림)에 나옵니다. 판정은 `추가 가능` / `RSS 없음(목록 페이지 방식 필요)` / `제외(robots.txt 불허)` / `접속 실패` 중 하나입니다.

## 6. 오류가 났을 때

| 증상(로그) | 원인 | 조치 |
| --- | --- | --- |
| `접속 실패(... CERTIFICATE_VERIFY_FAILED ...)` | 회사 보안 장비가 HTTPS 인증서를 바꿈 | IT에서 회사 루트 인증서(.pem/.crt)를 받아 `config.json`의 `ca_bundle`에 경로 입력 |
| `접속 실패(... timed out / getaddrinfo ...)` | 프록시 필요 또는 외부 접속 차단 | 명령 프롬프트에서 `set HTTPS_PROXY=http://프록시:포트` 후 실행. 막혀 있으면 IT 문의 |
| `robots.txt가 이 주소의 수집을 허용하지 않음` | 사이트가 자동 수집을 막음 | 그 출처는 `"enabled": false`로 끄고 `--file` 방식이나 수동 입력으로 |
| `HTTP 403` / `HTTP 404` | 차단되었거나 피드 주소가 바뀜 | 브라우저로 주소를 열어 확인 후 `feeds` 수정 |
| `RSS 형식이 아님` | 피드 주소가 HTML 페이지로 바뀜 | 사이트에서 RSS 주소를 다시 찾거나 출처를 끔 |
| `일정 없음` | 채용 글이지만 날짜 문장을 찾지 못함 | 정상일 수 있음. 놓친 글은 `--url`로 다시 읽고 결과를 확인 |
| 수집함에 '기업 매칭 필요' | Pool 이름·별칭에 없는 기업 | 수집함에서 비교기업을 골라 승인. 자주 나오면 Pool 별칭에 추가 후 다시 내보내기 |

연속 실패 횟수와 마지막 오류는 수집함 상단 '출처별 수집 상태'에도 나옵니다. 문제가 계속되면 `logs` 폴더의 그날 로그 파일과 `inbox.json`을 함께 전달해 주세요.
